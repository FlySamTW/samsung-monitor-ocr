# Samsung OCR 系統技術參考手冊 (Technical Reference)

本文件整合了系統的核心邏輯、開發演進歷程以及維護規則，是系統開發與除錯的唯一權威指南。

---

## 1. 核心辨識邏輯 (Core Logic v18.22)

### **A. 零記憶辨識律 (Zero Memory Policy)**

- **獨立性**：每一張照片都是一個獨立事件。系統在處理新照片前會強制清除對話歷史。
- **防止幻覺**：AI 禁止參考上一張的結果，必須以全新視角判讀目前照片。

### **B. 盤點式推理 (Inventory Reasoning)**

- **強制盤點**：AI 必須先列出畫面上所有看到的 S... 字串與價格數字，才允許進行邏輯判定。
- **證據對應**：輸出結果必須有盤點中的碎片作為依據，禁止「無中生有」。

### **C. 空間與尺寸雙重鎖定 (Spatial & Size Guard)**

- **垂直投影規則**：價牌的正中心必須落在主體螢幕支架/底座的水平寬度範圍內。
- **尺寸核對**：若螢幕標識 27 吋，價牌寫 32 吋，系統判定為「誤配」並強制定為 null。

### **D. 型號規律校驗 (Model Pattern Match)**

- **格式規範**：型號必須符合三星特徵前綴 (S/C/F/U/LS/WA)。
- **黑名單**：禁止輸出「SAMSUNG」、「27吋」等描述關鍵字作為型號。
- **標籤優先**：強制鎖定「機型 :」標籤右側字串。
- **穩定模式 (v18.26+)**：基於原始大圖的視覺通盤判讀。
- **UI 框架**：React / Vite (Dashboard) + Flask (API Backend)。

## 2. 開發歷程 (Version History)

### **v18.42 (最新)** - 結構化一體性與貪婪匹配 (Structural Unity & Greedy Match)

- **修正目標**：承認 `v18.41` 同色檢核的缺陷，改採更智慧的物理結構判定。
- **核心邏輯**：
  - **結構化一體性 (Container Check)**：不再單純比對顏色，而是要求 AI 識別「容器關係」。容許「粉紅底紙包含黃色價格框」（合法），但拒絕「左粉右黃物理分離」（違規）。
  - **貪婪提取 (Greedy Extraction)**：Regex 自動從雜訊中提取規律型號字串，解決 `412` 辨識失敗。

### **v18.40** - 實體歸屬鎖定與標籤一體性 (Phy-Align)

- **修正目標**：解決 `431` 拼接錯誤與 `424` 漏抓問題，平衡視覺對齊的嚴格度與彈性。
- **核心邏輯**：
  - **視覺歸屬 (Visual Grouping)**：取代死板的激光垂直線，允許 AI 依據視覺上的「歸屬感」判斷（如底座旁），救回偏移標籤。
  - **實體一體性 (Unity Check)**：強制檢查 Model 與 Price 是否位於「同一矩形邊界」內，嚴禁跨標籤組合。
  - **雙重視野平衡**：User Prompt 明確分工圖 1 (位置) 與圖 2 (讀字)。

### **v18.39** - 誠信校正與 FollowMe 匹配修復 (Integrity & FollowMe Fix)

- **修正目標**：移除技術文檔中關於「官方背書」的錯誤描述，還原工程真實性；修復 `FollowMe M7 32"` 匹配失敗問題。
- **核心邏輯**：
  - **匹配優化**：`ModelMatcher` 新增對雙引號 `"` 與尺寸單位的正規化移除，確保特規型號能通過後端驗證。
  - **文檔校正**：將「雙重視野」與「無狀態清洗」正確定義為專案內部的工程策略。

### **v18.38** - 垂直投影鎖定與標籤身份核對 (Vertical Laser Alignment & Tag Integrity)

- **修正目標**：解決 `431.jpg` 出現「跨標籤拼接」的問題（誤將鄰機標籤型號與本機價格組合）。
- **核心邏輯**：
  - **物理一致性強檢查**：在 Prompt 中定義「激光準星」概念，要求 AI 先鎖定底座中心垂直軸，再核對標籤紙張的顏色與完整性。
  - **禁止跨紙組合**：嚴禁「A 紙型號 + B 紙價格」，並將 `431` 樣例植入禁令指示。

### **v18.37** - FollowMe 智慧特規辨識 (FollowMe Smart Heuristic)

- **修正目標**：解決 FollowMe 系列因無實體掛牌導致的「無型號 / 無價格」誤判，利用獨特的工業設計特徵進行補全。
- **核心邏輯**：
  - **特徵解碼**：定義「白色立架 + 中間托盤」為 `FollowMe M7 32"` 的視覺唯一識別證。
  - **條件豁免**：當偵測到上述組合時，允許 AI 跳過「必須看到 S... 拼寫」的硬性規定，直接進行邏輯映射輸出。

### **v18.36** - 人格魅力與視覺平衡 (Vibrant Persona & Balance)

- **修正目標**：解決 `0.1` 低溫導致的輸出僵硬問題，賦予 AI 更像「真人專業員」的思考質感。
- **核心邏輯**：
  - **溫度回升**：設定為 `0.4`，在維持 OCR 精準度的同時，允許語言生成具備豐富的層次感。
  - **人格化指令 (Self-Talk)**：引導 AI 在分析時採用「第一人稱自言自語」風格，將單調的盤點轉化為具備觀察直覺的描述。
  - **視覺與物理絕緣**：保留雙圖傳輸與物理重設機制，確保人性化不以損害準確度為代價。

### **v18.35** - 徹絕緣與視覺緩存清除 (Stateless Purge)

- **修正目標**：徹底消除不同圖片間可能存在的型號「記憶殘留」現象，並優化 OCR 辨識穩定性。
- **核心邏輯**：
  - **低溫鎖定**：將 `temperature` 與 `top_p` 參數設為較低值 (0.1)，以提升輸出確定性 (Engineering Choice)。
  - **無狀態聲明**：在 Prompt 開頭加入顯眼的「全新照片/無記憶」指令，強制 AI 斷開上下文聯想。
  - **修復視覺機制**：重新激活 `v18.34` 的雙重視野，確保高清特寫圖確實被傳送（修正了代碼中的誤殺邏輯）。

### **v18.34** - 視覺通道深度修復與智慧對焦模式 (Dual-Focus Vision)

- **修正目標**：解決 `424.jpg` 解析度不足導致小字（粉紅貼紙）讀取失敗，以及 `412.jpg` 型號錨點不穩的問題。
- **核心邏輯**：
  - **恢復雙重視野**：AI 重啟傳輸「環境全景」+「局部高清特寫」。
  - **智慧導引**：明確指示 AI「空間判斷看全景，文字細節看特寫」。
  - **權限對齊**：細節圖具有物理像素級的文字最高優先權。

### **v18.33** - 識別退化修復與錨點強化 (Regression Fix & Anchor)

- **修正目標**：解決 `412.jpg` 在 `v18.32` 中因極小字型號辨識困難，轉而誤抓條碼數字（271...）的問題。

## 4. 實戰經驗庫 (Learned Experience)

### **特定案例處理 (Few-Shot Experience)**

- **遠景判定**：當畫面上超過 3 台完整螢幕且無近處價牌時，歸類為「遠景」。
- **螢幕狀態**：黑屏或藍屏應標註為「不合格」。
- **代碼禁令**：Odyssey 是系列名稱，G74 是代號，均不可取代 S27... 正式型號。

## 4. 雙重視野技術 (Dual Vision Strategy) —— v18.25 核心

為了解決 VLM 模型自動縮小 4K 圖片導致的小型文字模糊：

- **高清特寫 (Zoom-In)**：ImageProcessor 會利用 OpenCV 偵測矩形價牌區塊，並以原始解析度進行無損裁切。
- **對照組機制**：系統永遠同時發送「全景圖」與「裁切圖」，讓 AI 在確認主體座標的同時，擁有一個「高清放大鏡」來讀取正確型號。
- **降級保護**：若偵測不到價牌，系統自動回退至單一全景辨識模式。

## 5. 維護規則 (Maintenance Rules)

- **語言要求**：系統對外輸出與內部思考過程必須統一使用 **台灣繁體中文**。
- **數據完整性**：若看到價牌但不可讀，類別應標為 `不合格-照不清楚`。
- **備份機制**：每次重大 Prompt 更新後，應更新儀表板版本號以便追蹤。
