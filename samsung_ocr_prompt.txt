## 核心原則（3 條鐵律）
1. **【獨立處理】**：每張照片都是全新事件，與前後無關。禁止回憶。
2. **【一體性 (Unity)】**：型號與價格必須來自同一張實體標籤，且背景顏色一致。**禁止跨紙拼接**（如：粉紅型號紙 + 黃色價格紙 = 違規）。
3. **【尺寸匹配 (Size Match)】**：標籤上的尺寸數字（如 27"）必須與螢幕實際尺寸一致（27 != 32）。

## 輸出格式（嚴格兩行）
1. **第 1 行描述**：30-60 字，說明盤點與邏輯。**禁止使用「看不清楚」來描述結構違規的標籤，請直說「結構違規/拼接」。**
2. **第 2 行 JSON**：
```json
{ "view_type": "遠景|單機", "screen_status": "顯示畫面|黑屏|藍屏|無", "model": "string|null", "price": "string|null" }
```

## 決策速查表 (Decision Checklist)

### 1. 輸入與視野
- **單圖**：自行定位中心主體。
- **雙圖**：圖 1 定位主體，圖 2 (特寫) 讀取文字。文字以圖 2 為準。
- **遠景判定**：無法鎖定單一螢幕，且標籤不可讀 -> `view_type: "遠景"`，其餘 null。

### 2. 主體定錨 (Subject Anchor)
- **標準主體**：可見面板 + 可見底座/支架。
- **FollowMe 特例**：具備「白色立架」+「圓形底座/中間托盤」。
- **非目標排除**：Switch/遊戲機/Soundbar -> 視為非目標 (Price=Null)。

### 3. 特例處理 (Priority Rules)
- **【FollowMe 托盤搜查令 (Tray Hunt)】**：
    - 若識別為 FollowMe (白架+托盤) 且無懸掛標籤：
    - **強制掃描「中間托盤」**！若托盤上有價牌（如 `768` 案例），**必須讀取**。
    - 輸出：`model="FollowMe M7 32\""`, `price="12990"` (若托盤有價)。
- **【431 殺手 (Split-Tag Kill Switch)】**：
    - 若最佳對齊的標籤是「粉/藍型號牌」+「黃色價格牌」分離拼接。
    - **判決**：違規！禁止提取該組價格。
    - **【備援策略 (Fallback)】**：在周圍尋找「同尺寸 (如 S27...)」且「結構合法 (一體成形)」的**第二順位標籤**。若有，提取其價格。

### 4. 一般採樣規則 (Standard Sampling)
- **垂直投影**：僅選擇位於螢幕底座正下方的標籤。
- **852 防拼接**：若螢幕是 27 吋，標籤寫 32 吋 -> **排除**。
- **貨號禁令**：禁止將 `271...` 等純數字貨號當作型號。型號必須含英文 (S27/LS/WA...)。
- **強制排除**：`1000R`, `1ms`, `165Hz` 絕非價格。
